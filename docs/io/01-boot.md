# FM-1 Boot, Clocks and Interrupts

Reverse-engineered from `app.bin` (pi32v2 ISA, flash XIP VMA `0x02000000`) on
the JieLi AC791N/WL82 target. Every claim carries the address it was read from;
`[high|med|low]` marks confidence from the master DB (`analysis/db.json`),
refined by manual review. Code
citations name the enriched shard the disassembly was taken from
(e.g. `shard_020000a0_020020de.txt`); reset-vector instructions before the first shard
were re-verified against the raw bytes of `app.bin` with the vendor pi32v2 objdump.

Address-space note: all `0x0200xxxx` values are **runtime XIP addresses** — verified to
be identical to `app.bin` file offset + `0x02000000` (the CRT copies `.data` from
`0x02084820`, and the RAM early-init code it lands on is provably at file offset
`0x84820`; there is no load skew). Functions whose address falls in
`0x02084820..0x0208E59C` are the `.data` **flash image**: they execute from RAM at
`0x01C00000 + (addr - 0x02084820)` after the CRT copies them there.

## 2. Reset vector and CRT startup (`0x02000000`)

Raw bytes verified against `app.bin`. The listing below is exact.

```
0x02000000  goto 0x02000004                ; reset vector (0x02000002 holds an rts)
0x02000004  sp  = 0x01C14BB4               ; main stack
0x0200000A  ssp = 0x01C15BB4               ; system/exception stack
0x02000010  call 0x020000C6                ; boot_hwinfo_save(r0 = SPL boot-param ptr)
0x02000016  zero .bss:  r3 = 0x01C09E7C, r1 = 0, r2 = 0x17380 >> 2
0x0200002C  copy .data: r4 = 0x01C00000 <- r1 = 0x02084820, r2 = 0x9E7C >> 2
0x02000048  overlay:    r0 = 0x04000120, r1 = 0x02084820, r2 = 0
            if (r0 != r1) call 0x02042642  ; memmove — length is 0 in this build
0x02000068  zero-fill overlay (length 0)
0x0200007E  call 0x01C00D68                ; RAM-resident early init (see §2.1)
0x02000084  call 0x02058A64                ; "system init" — an empty stub (single rts)
0x0200008A  call 0x020053DE                ; boot_record_load
0x02000090  r6 = 0x02001C24
0x02000096  goto r6                        ; tail-jump into clock/board bring-up (see §5)
```

Notes on each step:

- **`boot_hwinfo_save 0x020000C6`** `[high]` — copies the SPL boot-parameter struct
  (pointer in `r0` on entry) into the hw-info block at `0x01C7FD50`. Field map (from
  `shard_020000a0_020020de.txt`):

  | hwinfo offset | source | meaning |
  |---|---|---|
  | `+0` (u8) | `[param+0]+13` | chip id byte |
  | `+16` (u64) | `param+4` | two 32-bit words (sizes; read as a pair elsewhere) |
  | `+24` (u32) | `[param+0]+8` | word from param block |
  | `+28` (u16) | `param+12` | halfword |
  | `+30` (u16) | `param+14` | halfword |
  | `+32` (u64) | `param+16` | **BT MAC (6 B) + crc16 (2 B)** — validated by `syscfg_read 0x02002612` id 102 (`shard_02002154_02003b52.txt`) |

- **`boot_record_load 0x020053DE`** `[low]` — CRC16s (hardware CRC, `chip_crc16
  0x020025DA`) a 78-byte boot record at `0x01C7FD8A`, compares against the stored
  halfword at `0x01C7FD88`, builds a 32-bit word from `h[+12]`/`h[+14]` into
  `[0x01C0E670+140]`, then zeroes the record area (`shard_02003b7c_02005bb2.txt`).

- **Tail jump `goto 0x02001C24`** `[high for the bytes, med for semantics]` — see §5
  for the anomaly discussion.

### 2.1 RAM-resident early init `0x01C00D68` `[med]`

Runs from RAM (flash image offset `0x85588`, i.e. `.data + 0xD68`). Verbatim decode
from the binary:

- Pokes the interrupt-controller SFR `0x1EEE008` (waits for bit 14, clears mask
  fields, programs per-priority bit masks).
- Clears SRAM banks at `0x1F00000..0x1F04000` and `0x1F08000..0x1F0A000`, plus
  two 512-byte blocks flanking a 3584-byte hole.
- Reads chip straps `0x40400` (bit 11) and `0x40500` (bit 0) and ORs `0x200` into
  `0x1EEE008` accordingly.
- `memmove(0x1F28000, 0x0208E69C, 32)` then `memset(0x1F28020, 0, 0)` — copies a
  32-byte config block (past the end of `.data`, from flash `0x0208E69C`).

## 3. SPL (second-stage loader) handoff

The mask ROM loads `uboot.boot` (14,384 B) to RAM and runs it; its header contains
the load address `0x01C02000` (bytes at offset 4). The SPL:

- brings up the SPI-NOR flash and clocking sufficient for XIP,
- parses the `app_area_head` flash file table in the download container (entries for
  `app.bin`, `cfg_tool.bin`, plus `VM`/`PRCT`/`CODE`/`BTIF`/`AUTO`/`USR` section
  tags), and maps/verifies the app at XIP `0x02000000`,
- reads fields from the app vector area (e.g. the `ssp` value at `app+12`,
  `0x01C15BB4`) when preparing the handoff,
- jumps to `0x02000000` with a **boot-parameter struct pointer in `r0`**
  (consumed by `boot_hwinfo_save 0x020000C6`; the SPL side of the protocol is
  `[low]` — inferred from the app-side consumers).

Container metadata (`jlfw.yaml`) lists `entry-point: 33554720` = `0x02000120`, and
the CRT tail-jumps to `0x02001C24` — both exactly 0x120 above the reset vector
(`0x02000000`) and the bring-up function start (`0x02001B04`) respectively. See the
anomaly note in §5.

## 4. Exception/interrupt vector area (`0x02000098`–`0x020000C4`)

```
0x02000098  usp = 0x01C15EB4               ; cpu1 entry: user/system stack
0x0200009E  sp  = 0x01C16EB4
0x020000A4  reti = 0x01C023D6
0x020000AA  rti                            ; cpu1 starts by "returning" into RAM code
0x020000AC  trigger                        ; software-interrupt trigger instruction
0x020000B0  [--sp] = {sp,ssp,usp,icfg,psr,rets,retx,rete,reti}
0x020000B4  [--sp] = {r15-r0}              ; full 25-word context save
0x020000B8  r0 = sp
0x020000BC  call 0x020002A2                ; C dispatcher, r0 = saved-frame pointer
0x020000C2  goto 0x020000C2                ; spin (never returns)
0x020000C4  rts
```

- The vector at `0x020000B0` is the **common exception/IRQ entry**; it saves the
  full pi32v2 context and passes the frame to `irq_c_dispatch 0x020002A2` `[high]`
  (`shard_020000a0_020020de.txt`).
- The entry at `0x02000098` programs cpu1's stacks and `rti`s to `0x01C023D6` —
  RAM-resident code (the `.data` image region `0x02086be4`+ is the cross-core IPC
  path; `cpu_ipc_call_sync` runs at `0x01C023C4`). This is the cpu1 hardware boot
  vector `[med]`.
- `irq_c_dispatch 0x020002A2` scans the interrupt-controller SFRs (`0x1EEE000`
  region, per-core pending/enable arrays), dispatches per-IRQ handling through
  `tbb` jump tables (`0x0200037E` for IRQ 2–15), wakes tasks, and calls the ROM
  diagnostic service `0xFFC00EA8` before hanging on fatal error `[high for
  existence, med for dispatch detail]`.

### 4.1 `request_irq 0x020016D2` `[high]`

Exact signature (matches the BR23 SDK convention and all observed call sites):

```
request_irq(index, priority, handler, cpu)      ; r0, r1, r2, r3
```

Behaviour (from `shard_020000a0_020020de.txt`):

- Looks up `index` in the 3-byte default-priority table at `0x0204DE68`
  (`{irq, prio, cpu}` records; `0xFF` = end, `0xFE` = reserved). On a match the
  table's `prio`/`cpu` override the arguments. First records in the image:
  `(0x14, 0x29, 0x03)`, `(0x02, 0x9A, 0x29)`, `(0x03, 0x02, 0xB8)` — field
  semantics per the code; raw values as shipped.
- If `handler != 0`: stores it into the **RAM vector table**:
  `[0x01C7FE00 + index*4] = handler`.
- Programs the per-CPU enable/priority nibble in the interrupt-controller arrays:
  `prio` is encoded as `((prio & 7) << 1) | 1` (bit 0 = enable) into a nibble of
  the 8-word arrays at `0x1EEF100` (cpu0) or `0x1EEF300` (cpu1); `cpu == 0xFF`
  means "current core" (`cnum`).
- Wraps the SFR update in `irq_master_disable/enable` (`0x0200167E`/`0x0200168A`:
  clear/set `icfg` bit 8).

Known registrations:

| IRQ | prio | handler | cpu | registered by |
|---|---|---|---|---|
| 1 | 7 | `0x020001CC` | current (0xFF) | `cpu_link_irq_init 0x02001758` (IRQ0/1 = exception/syscall per BR23 convention) |
| 2 | 7 | `0x01C06EA8` | 0 | `irq2_ram_handler_install 0x02001A60` (RAM-resident) |
| 3 | 1 | `0x0205BE92` | 0 | `os_start 0x0205A6B6` — **OS tick** (see 02-rtos.md §2.2) |
| 28 | 7 | `0x02000616` | 0 | `cpu_link_irq_init 0x02001758` |
| 37 | 5 | `0x01C045F6` | 0 | `board_init 0x0200417E` (RAM-resident; keys/input) |
| 44 | 2 | `0x02033518` | 0 | `main 0x0200457A` body |
| 122 | 4 | `0x01C0470C` | 0 | `board_init 0x0200417E` (RAM-resident) |
| 126/127 | 0 | `0x020419DA` | per-cpu | `os_start 0x0205A6B6` — **context-switch SWI** (`0x7F - cnum`) |

`irq_unregister 0x02026478` `[med]` clears the RAM slot and the ICFG nibble.

## 5. Clock/PLL init

Two functions cooperate; both in `shard_020000a0_020020de.txt`.

### 5.1 `pll_clock_init 0x020000F8` `[high]`

`pll_clock_init(ref_hz, target_hz, r2, r3)` — programs the PLL SFR block at
`0x16A00` (PLL_CON0/1/2). Behaviour:

- `r3 == 0` path: `r1 = (target_hz / 1_000_000) << 1`, clamped to 576; feedback
  divider field `r4 = (r1 << 18) - 0x80000` (default `0x7780000`).
- Zeroes `0x16A08`/`0x16A0C`, waits (`0xFFC05C4C` ROM delay, r0 = 10/100 µs),
  sets ref-select and enable fields in `0x16A08` (`|= 4`, `|= 0x18`, optional
  `0x20`/`0x40` when `r2 != 0`).
- `0x16A00`: enable (`|= 1`), then a sequence of masked field writes
  (`|= 0x10, 0x20, 0x80, 0x400, 0x800`), reference divider `r0 = (ref_hz/1e6) << 12
  - 8192`, feedback `|= r4`, `|= 4`, delay, `|= 2` (lock), delay, `&= ~4`, final
  delay 100.

The second function in the same DB entry (starts `0x020001AE`) is the system-clock
switch wrapper: saves SFRs `0x40404`, `0x10010`, `0x5101C` to the stack, calls ROM
`0xFFC05064`, calls `pll_clock_init(24000000, 240000000, 0, 0)` (seen at
`0x020001F0` — **PLL ref 24 MHz → 240 MHz**), then programs `0x40404` (`|=
0x145, 0x40, 0x100`), `0x4040C` (`|= 0x60000200`), restores the saved registers,
writes `0x10014 = 10000`, and calls ROM `0xFFC050D4` `[high]`.

### 5.2 `clock_board_init 0x02001AB0` (DB anchor; body at `0x02001B04`) `[high]`

The DB entry `0x02001AB0` (1194 B, `shard_020000a0_020020de.txt`) is two things:

1. **`0x02001AB0` — "create task from clock/device node" helper**: looks up a node
   by name (`clk_node_find 0x02001A74`, table `0x0204DE74`), and spawns its task via
   `os_task_create_static 0x0205A4AC` or `os_task_create 0x0205A5DE`.
2. **`0x02001B04` — the real boot continuation** (the function the CRT tail-jump
   logically enters; see anomaly note below):

   - `cli`, bumps `irq_lock_cnt[cnum]` (`0x01C0953C`), `csync`.
   - ROM config calls (`0xFFC00F2E` ids 0/12 via wrapper `0x02001970`;
     `0xFFC00F94` ids 32/64/16 via wrapper `0x02000848`, plus id 23 arg 64
     direct; `0x13E04 |= 0x10`).
   - Reads clock SFRs `0x10008`, `0x10008+6552` (= `0x119A0`), `0x16A00`; clears
      per-core reg `0x1EEF0F0`.
   - **Reference clock detect**: `if ([0x119A0] & 0x0C000000) != 0x08000000` →
     24 MHz, else 40 MHz `[high]` — FM-1 uses the 24 MHz crystal path.
   - Derives the clock tree with bitfield extracts (`uextra`) of the SFRs: PLL
     feedback `r14 = (pll_fb + 2) * (ref / (refdiv + 2))`, sys clock into the clock
     struct at `0x01C1FF0C` (`[+8]`, `[+12] = 48000000`, `[+16]/[+20]` bus
     divisors, `[+24]` strap mirror, `[+28]/[+36]` derived). Paths include
     `192000000`-based and `480000000`-based branches.
   - Programs the PLL directly once more (same `0x16A00` sequence as
     `pll_clock_init`), ROM `0xFFC02324` with r0 = 4.
   - Stores `sysclk/100` to `0x1EEF0F4` (tick-timer scale), marks
     `[0x01C1FF0C+4] = 0x2D`.
   - `irq_mask_arrays_clear 0x02001696` (zero per-core enable arrays, master-enable
     interrupts).
   - `irq2_ram_handler_install 0x02001A60` → `request_irq(2, 7, 0x01C06EA8, 0)`.
   - `cpu_link_irq_init 0x02001758` — registers IRQ1 (`0x020001CC`) and IRQ28
     (`0x02000616`), programs per-core control SFRs (`0x1EEF0D0` region), writes
     `0x13400 = 0x6D`, and sets the per-core exception stack pointers
     (`0x01C14BB4/0x01C15BB4` cpu0, `0x01C15EB4/0x01C16EB4` cpu1) `[med]`.
   - `os_mutex_create 0x0205A09C` on the global at `0x01C0E670+2116`.
   - A run of ROM `0xFFC00F2E` writes (ids 208–223, 175, 174, 173, 148, 17) —
     chip configuration defaults `[low for meaning]`.
   - `cpu1_boot_start 0x0205A0C8` — writes **`0x020001B8`** to the cpu1 mailbox
     `0x01C7FFF8`, sets `0x10008 |= 0x8`, doorbells via `0x1EEE004` (`|= 0x8`,
     `&= ~2`), spins until cpu1 acks via `b[0x01C1FF08]`, restores `0x10008`
     `[med]`. (The stored entry `0x020001B8` is mid-function under static decode —
     same anomaly class as `0x02001C24`; see below.)
   - `os_init 0x0205A10A` — sets the OS-running flag and the task-queue registry
     list head.
   - Spawns the boot task through `0x02001AB0` with fallback entry `0x0200473C`
     (inside `main`'s range) and a name from the task-info table.
   - Decrements `irq_lock_cnt`, `csync`, `sti`, and calls **`os_start 0x0205A6B6`**;
     returns 0 (so the CRT's `goto` never comes back through the reset path).

**Anomaly note (important for reimplementation).** The CRT tail-jump literal is
`0x02001C24` (raw bytes `c6 ff 24 1c 00 02` at `0x02000090`, re-verified). Under
the vendor linear-sweep decode — re-verified by disassembling *from* `0x02001C24`
with the pi32v2 objdump — `0x02001C24` is mid-function: the code there reads
`r2` (`0x10008`), `r5` (`0x01C1FF0C`) and `r12`, which are only initialized by the
prefix at `0x02001B04..0x02001C23`. The prefix is a coherent function
(matching `{rets, r15-r4}` prologue/epilogue) that ends with `os_start`. So the
**functional boot-continuation entry is `0x02001B04`** `[high]`; the shipped
literal is +0x120 from it — exactly the same +0x120 delta as the container's
`entry-point: 0x02000120` vs the `0x02000000` reset vector (the `app_area_head`
in the download container is 0x120 bytes). The most plausible explanation is that
the pack/download tooling's entry-point accounting includes the 0x120-byte
app-area header; treat `0x02001B04` as the entry to replicate. `[med]`

### 5.3 `clk_get 0x0200197E` `[high]`

`clk_get(name)` — string compares against the clock-name table at `0x0204EA20`
(`"uart"`, `"wifi"`, …) and returns frequencies from the clock struct at
`0x01C1FF0C` (`[+8]` sys, `[+12]` 48 MHz, `[+16]/[+20]` bus, `[+28]`); unknown
names return -22 (`-EINVAL`). One branch reads `0x40204` (chip strap) to divide a
clock by `strap+1`; the xtal detect branch returns 24000000 or 40000000.

## 6. main() and the initcall flow

`main 0x0200457A` (DB anchor, 3684 B; substantive body from `0x0200461C`,
`shard_02003b7c_02005bb2.txt`) `[med]`. Boot order inside:

1. `os_sem_create 0x0205A7C2` on `0x01C0E670+2036` (timer-task wake semaphore).
2. Initializes the usr-timer tick-list heads at `0x01C0E670+992/+1000`.
3. Calls `0x0201F5A` (boot-time timer-subsystem init `[low]`) and
   `lp_timer_calibrate 0x02001FA8` — tick divisor setup, programs P33 over SPI
   `[med]`.
4. Spawns the two timer tasks via `0x02001AB0` (node table `0x0204DE74`):
   `sys_timer` task (scan body at `0x02031AF4`, loop at `0x02031B7E`) and
   `usr_timer` task (`0x02031E88`), named from the table.
5. **Module init table** `0x0208392C..0x02083944` (12-byte entries
   `{name, dev, arg}`): calls ``[dev+4](entry, arg)``; fatal-hangs on failure.
6. **Initcall level 1** `0x02083894..0x020838A4`, **level 2**
   `0x020838A8..0x020838AC`: arrays of 4-byte function pointers, called in order.
7. `memset(0x01C09548, 0, 496)` (system message-queue area), then board/chip
   config: `clk_get(...)/8000000` into `b[0x01C09548+97]`, ROM config writes
   (`0xFFC00F2E` ids 48, 114, 49, 84, 19, 20, 155, 50, 54, 55, 116, 144, 146;
   `0xFFC00F94` ids 0x80AA, 17, 51; `0xFFC00F6C` misc), SFR pokes at
   `0x13E00`/`0x13600`, `request_irq(44, 2, 0x02033518, 0)`.
8. `board_init 0x0200417E` (see §7).
9. Enters the device/power message loop (`0x0200520A`): `os_taskq_pend
   0x0205B690`, dispatches on messages with the magics `0x0A1B2C00`/`0x0A1B2BFF`,
   drives device nodes under a mutex; the per-app helper at `0x0200457A` head is
   called with 0..3 during this phase.

The task created by the boot continuation (§5.2) runs the main application state
machine from its node-table entry (fallback entry `0x0200473C`).

## 7. board_init `0x0200417E` `[med]`

(`shard_02003b7c_02005bb2.txt`.) Observed operations, in order:

- Opens a device by name (`dev_open 0x020033C4` on a `0x0204EA42`-table string),
  records `[0x01C0E670+260]` and `+0x4000` into `[0x01C0E670+256]`, closes it.
- Installs two pointer tables at `[0x1C0E670+338*4]`/`[+339*4]`.
- Copies a 118-byte config block to `0x01C0E670+4776`, stamps it with `0x50505050`
  patterns (tag bytes).
- `request_irq(37, 5, 0x01C045F6, 0)`, `request_irq(122, 4, 0x01C0470C, 0)` —
  RAM-resident handlers.
- Programs the `0x11E00` peripheral (display/SPI: `[+0] = 0x6020`, `[+4] = 0x1D`,
  `[+12]`, `[+16] = 2`, `[+0] |= 1`); `0x51020 |= 0x20000`.
- Registers periodic sys timers (`sys_timer_add 0x02004036`): callbacks
  `0x020245C2` (20 ms), `0x020248CA` (50 ms), `0x02024478` (2 ms), `0x02021108`
  (2 ms), `0x02021356` (2 ms).
- Builds the 160-byte "audio server" state (magic `0xAC56`, buffer sizes 256/256/
  8192, float constants `0x3F801630`, `0x3F7F44D4`, `0x3B149B92`), fills a
  1025-entry table (coefficients), stores the struct at `[0x1C0E670+252]`.
- Creates the audio server task: `os_task_create 0x0205B1D0` with name from
  `0x0204EA42+1335`, prio 5, stksize 1024 (words), qsize 0, entry `0x02022E32`
  (arguments reconstructed from the call site at `0x02004570`; see 02-rtos.md
  §3.2 for the exact ABI of this build).
